# Claim Set: Agent Authorization Workflow

## Independent Claims

### Claim 1

A computer-implemented method for authorizing a software agent to act on behalf of a principal, the method comprising:

receiving a task request associated with the principal;

identifying the software agent designated to perform at least a portion of the task request;

determining authorization constraints based on the task request, an identity of the principal, an identity of the software agent, and one or more policies;

generating a scoped authorization artifact encoding a bounded permission set for the software agent;

intercepting an action request generated by the software agent prior to execution of the action request;

validating the action request against the scoped authorization artifact using a compound authorization decision that includes at least a principal decision, an agent decision, and a delegation decision; and

selectively permitting, denying, modifying, or escalating execution of the action request based on the validating.

### Claim 2

The method of claim 1, wherein the compound authorization decision permits execution only when the principal decision, the agent decision, and the delegation decision each resolve to allow.

### Claim 3

The method of claim 1, wherein the scoped authorization artifact is bound to at least one of a task identifier, a tenant identifier, a permitted tool set, a permitted action set, a resource scope, a time window, an invocation limit, a spending threshold, a data sensitivity class, or a maximum delegation depth.

### Claim 4

The method of claim 1, wherein generating the scoped authorization artifact comprises cryptographically signing the scoped authorization artifact.

### Claim 5

The method of claim 1, wherein the scoped authorization artifact includes at least a delegation identifier and a root delegation identifier.

### Claim 6

The method of claim 1, wherein the authorization constraints include one or more classification caps associated with one or more classification hierarchies.

### Claim 7

The method of claim 1, wherein the authorization constraints include a maximum action sensitivity tier for the software agent.

### Claim 8

The method of claim 1, wherein intercepting the action request comprises intercepting at least one of an API call, a database query, a document retrieval, a network request, a payment operation, a code execution request, or a downstream agent invocation.

### Claim 9

The method of claim 1, further comprising computing a contextual risk value associated with the action request and dynamically narrowing the bounded permission set when the contextual risk value satisfies a threshold condition.

### Claim 10

The method of claim 9, wherein dynamically narrowing the bounded permission set comprises reducing an allowed tool set, reducing a resource scope, lowering an action sensitivity tier, suspending execution, or requiring additional approval.

### Claim 11

The method of claim 1, further comprising determining that the software agent requests delegation to a secondary software agent and, in response, generating a derivative authorization artifact for the secondary software agent, the derivative authorization artifact having a permission scope no broader than the scoped authorization artifact.

### Claim 12

The method of claim 11, wherein the derivative authorization artifact includes a parent delegation identifier that references the scoped authorization artifact.

### Claim 13

The method of claim 11, wherein generating the derivative authorization artifact comprises enforcing that at least one of classification caps, allowed actions, allowed tools, or resource constraints is narrowed relative to the scoped authorization artifact.

### Claim 14

The method of claim 1, further comprising revoking the scoped authorization artifact before expiration in response to a policy change, anomaly detection event, principal withdrawal, trust-tier change, or attempted scope escalation.

### Claim 15

The method of claim 14, further comprising revoking one or more derivative authorization artifacts associated with the scoped authorization artifact.

### Claim 16

The method of claim 1, further comprising recording provenance data associating the principal, the software agent, the task request, the scoped authorization artifact, and one or more action requests.

### Claim 17

The method of claim 16, wherein the provenance data further associates one or more delegation events and one or more generated outputs.

### Claim 18

The method of claim 16, wherein the provenance data is stored in an append-only audit store or tamper-evident ledger.

### Claim 19

A system comprising one or more processors and memory storing instructions that, when executed by the one or more processors, cause the system to:

receive a task request for execution by a software agent on behalf of a principal;

evaluate one or more policies and contextual factors associated with the principal, the software agent, and a delegated scope;

issue a scoped authorization artifact bound to the task request;

enforce the scoped authorization artifact during runtime across a plurality of tool or service invocations initiated by the software agent;

dynamically update or revoke the scoped authorization artifact in response to changed execution conditions; and

record provenance data associating the principal, the software agent, the scoped authorization artifact, and the plurality of tool or service invocations.

### Claim 20

The system of claim 19, wherein the system comprises an identity service, an agent registry, a policy engine, an authorization issuer, an enforcement gateway, a delegation manager, a risk engine, and an audit subsystem.

### Claim 21

The system of claim 19, wherein the enforcement gateway is configured to deny the plurality of tool or service invocations unless a principal decision, an agent decision, and a delegation decision each resolve to allow.

### Claim 22

The system of claim 19, wherein the delegation manager is configured to issue derivative authorization artifacts for downstream agents and to enforce a maximum delegation depth.

### Claim 23

A non-transitory computer-readable medium storing instructions that, when executed by one or more processors, cause the one or more processors to:

receive a task request associated with a principal;

generate a task-bound authorization artifact for a software agent;

validate runtime actions of the software agent against the task-bound authorization artifact using a compound authorization decision;

generate a derivative authorization artifact for a downstream software agent when delegation is permitted; and

store provenance records linking principal approval, authorization issuance, runtime actions, delegation events, and generated outputs.
