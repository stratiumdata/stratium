# Release note — v0.1.0

The first tagged release of Stratium, and a **pre-release**: settings, wire
contracts and defaults can still change between versions.

It contains everything on `main` up to 26 November 2026: the policy decision
point (`stratium-pdp`), the admin plane and its console (`stratium-pap`), the
enforcement point in all its modes (`stratium-pep`), the Python SDK, and the
LiteLLM guardrails.

**If you are installing for the first time,** start at the
[quickstart](../quickstart.md). Nothing below is required reading, though
"Limits and their defaults" is worth a look before you go to production.

**If you are running a checkout of `main`,** this release does not upgrade
cleanly from most earlier points. Read "Before you upgrade" first. Changes are
marked with the pull request that made them, so you can skip what you already
have.

## Before you upgrade

### 1. Upgrade the PEPs and SDKs before the PDP

A caller from this release works against an older PDP, which ignores fields it
does not know. The reverse is not true. A PDP from this release refuses older
callers in three places:

- `GetApproval` requires the delegation's token (#61). An older `stratium-pep`
  or SDK polls without one, is refused, and every escalation it is waiting on
  ends as a denial.
- `IssueToken` requires a token this PDP issued for the same delegation (#8).
- Creating a child delegation requires the parent's token (#8).

### 2. Give the PDP its required settings

The PDP refuses to start without each of these. None has a default.

| What | Settings | Since |
|---|---|---|
| TLS for gRPC | `STRATIUM_TLS_CERT_FILE` and `STRATIUM_TLS_KEY_FILE`, or `STRATIUM_GRPC_INSECURE=true` to keep plaintext | #5 |
| Who a session is for | `STRATIUM_PRINCIPAL_OIDC_ISSUER`, `STRATIUM_PRINCIPAL_OIDC_AUDIENCE`, `STRATIUM_PRINCIPAL_CLAIM`, or `STRATIUM_PRINCIPAL_AUTH_INSECURE=true` for local development | #9 |
| Proof-of-possession | `STRATIUM_DPOP_FRESHNESS_WINDOW`, with `STRATIUM_PEP_EXTAUTHZ_ALLOWED_HOSTS` and `STRATIUM_PEP_PROXY_PUBLIC_URI` on those two PEP modes | [the August release note](2026-08-17-sender-constrained-tokens.md) |

Three things follow from them:

- **Each PEP must match the PDP's transport.** A PEP is on TLS by default. For
  a private CA set `STRATIUM_PEP_PDP_CA_FILE`; for plaintext set
  `STRATIUM_PEP_PDP_INSECURE=true` (`insecure=True` in the SDK). A mismatch
  denies every call with a TLS error.
- **`STRATIUM_PRINCIPAL_CLAIM` must name the same claim as
  `STRATIUM_PAP_APPROVER_CLAIM`.** An approval is valid only when the approver
  the PAP identifies is the principal the PDP recorded.
- **`STRATIUM_PRINCIPAL_OIDC_AUDIENCE` should differ from
  `STRATIUM_PAP_OIDC_AUDIENCE`,** with a separate client at your identity
  provider, so neither service accepts a token meant for the other (#52).

`stratium-pep session-start` reads the principal's token from the file named
by `STRATIUM_PEP_PRINCIPAL_TOKEN_FILE`.

### 3. Check the database role

The PDP and the PAP refuse to start when their database role is a superuser or
has `BYPASSRLS` (#50).

### 4. Let the migrations run

The PDP applies pending migrations at start when
`STRATIUM_MIGRATION_DATABASE_URL` is set. There are 30. The eight most recent:

| Migration | What it does | Note |
|---|---|---|
| `000023` | `approvals.used_at`, for single-use approvals (#50) | |
| `000024` | `delegations.bound_jkt`, a column grant, and a replaced trigger (#60) | |
| `000025` | `policies.protected`, default `false` (#63) | |
| `000026` | An index over pending approvals (#64) | Blocks writes to `approvals` while it builds |
| `000027` | Indexes for the paged lists and per-principal lookup (#66) | Blocks writes to `approvals` and `delegations` while they build |
| `000028` | Lets the PDP's role delete expired delegations and approvals, and nothing unexpired (#71) | |
| `000029` | `session_budgets`, the shared per-session call budget (#72) | An unlogged table |
| `000030` | Pins the search path of the tenant epoch trigger (#73) | |

The index migrations are plain `CREATE INDEX`. On large tables expect a brief
pause in new delegations and escalations while they build.

### 5. Run the hook installer again

`deploy/stratium install` now writes a `PreToolUse` timeout sized from your
approval and connect timeouts (#13), `"onFailure": "block"` (#15), and the
`PostToolUse` entries that report completed tool calls (#16). An install made
before those has a timeout of `10`, which is shorter than an approval wait.

### 6. Building from source needs Go 1.26 (#12)

## Breaking changes

### Sessions and tokens

- **`Decide` checks the subject.** It must be the principal the chain's root
  delegation was issued for (#8).
- **A root delegation needs the principal's OIDC token** (#9); see step 2.
- **A delegation lives at most 24 hours** unless `STRATIUM_MAX_DELEGATION_TTL`
  says otherwise. A longer `ttl_seconds`, including
  `STRATIUM_PEP_TTL_SECONDS` above 86400, is refused (#17).
- **A delegation is bound to at most one key** (#60). Once a DPoP key is bound
  for a session, the bearer token in its session file stops working. A session
  shared between `proxy`/`extauthz` and `hook`/`mcp` must become two sessions.
  A bound delegation cannot have children, and `ReportToolUse` refuses it.
- **An approval allows one call** (#50). Presenting it again is denied with
  `approval ... has already been used`. A refused attempt does not use it up.
- **`GetApproval` needs the delegation's token** (#61); see step 1.

### Decisions that come out differently

- **The shell classifier rates more commands higher** (#14). `READ_ONLY` is an
  allowlist: any redirection, pipe or expansion rules it out, so `ls $HOME`
  now rates `INTERNAL_MODIFY`. More commands rate `DESTRUCTIVE`, among them
  `find ... -delete`, `git reset --hard`, `git clean -f`, `git branch -D` and
  `rm` with long or trailing flags.
- **Under an `id_prefix`, shell commands must name files by full path** (#54).
  A bare file name is checked as a path, and a command that uses `$`, a
  backtick, or an unquoted `*`, `?`, `[` or `{` is denied.
- **Tool input must read one way** (#48). `Decide` refuses input in which two
  keys of one object differ at most in capitalization, such as `Name` and
  `name`.
- **MCP resource reads and prompts are decided** (#47). `resources/read`,
  `resources/subscribe` and `prompts/get` are tools a delegation must hold.
  Add them to `STRATIUM_PEP_REQUESTED_TOOLS`. Behind agentgateway, add the
  methods to the processor's `methods` map; `resources/subscribe` is not
  decided there.
- **Rego policies cannot reach outside the process** (#11). A stored policy
  that calls `http.send`, `net.lookup_ip_addr` or `opa.runtime` no longer
  loads, and the PDP denies for that tenant until it is edited.
- **Policy sees the real agent when a session starts** (#58). A policy that
  reads `context.agent` or `input.agent` used to see a disabled agent with a
  zero id at that point.

### The enforcement point

- **`hook` does not cache decisions** (#10). Every call asks the PDP, and an
  unreachable PDP denies at once. `mcp` caches in memory only.
- **`proxy` does not forward Stratium's own metadata** (#49): `authorization`,
  `dpop` and `stratium-approval-id`. Set
  `STRATIUM_PEP_PROXY_FORWARD_CREDENTIALS=true` if your target reads them.
- **A proxied call ends after an hour** (#67), with `DEADLINE_EXCEEDED`. Raise
  `STRATIUM_PEP_PROXY_MAX_STREAM_DURATION` for longer streams.
- **The session file's mode is checked** (#47). `hook`, `report` and `mcp`
  refuse one that group or others can read. Run `session-start` again.
- **A Python SDK `Session` keeps one delegation** (#49) and renews its token.
  Code that holds a `Session` past its delegation's lifetime should check
  `Session.expired` and build a new one.

### The admin plane

- **Editors can tighten, not relax** (#57). An operator with the `editor` role
  can no longer create resource label rules or tool catalog entries, lower a
  rule's level or an entry's tier, raise an agent's trust tier, or resume a
  suspended or disabled agent. Seed scripts that did these with an editor
  token need an admin token.
- **Editors create agents at trust tier 0 only** (#63).
- **`GET /v1/approvals` and `GET /v1/delegations` are paged** (#66). They
  return the newest 100 rows, 500 at most with `?limit=`. The body is still an
  array; the next page's URL is in a `Link` header with `rel="next"`. A script
  that read the whole list in one request must follow it.
- **Old sessions disappear from those lists** (#71). See "Retention" below.

### The development stack

- Every published port in `deploy/docker/docker-compose.yml` is bound to
  `127.0.0.1` (#12).

## Limits and their defaults

Until this release most of these had no limit at all. Each default is meant to
be far above ordinary use, and each is a setting. The ones most likely to need
changing are in bold.

### PDP

| Setting | Default | What it bounds |
|---|---|---|
| **`STRATIUM_MAX_CONNECTIONS_PER_IP`** | `100` | Connections from one address (#69) |
| `STRATIUM_MAX_CONNECTIONS` | `10000` | Connections in all (#69) |
| `STRATIUM_MAX_CONCURRENT_STREAMS` | `256` | Calls in flight on one connection (#17, #68) |
| `STRATIUM_MAX_CONNECTION_IDLE` | `5m` | How long an idle connection is kept (#68) |
| `STRATIUM_REQUEST_TIMEOUT` | `10s` | How long one call may run (#56) |
| **`STRATIUM_SESSION_CALLS_PER_SECOND`** | `20` | Calls a second for one session (#65) |
| `STRATIUM_SESSION_CALLS_BURST` | `100` | Calls at once for one session (#65) |
| `STRATIUM_MAX_PENDING_APPROVALS` | `20` | Approvals one session may have waiting (#64) |
| `STRATIUM_FAILED_TOKEN_AUDIT_PER_SECOND` | `5` | Audit entries a second for tokens that do not authenticate (#53) |
| `STRATIUM_FAILED_TOKEN_AUDIT_BURST` | `20` | The burst above that rate (#53) |
| `STRATIUM_DB_MAX_OPEN_CONNS` | `20` | Database connections (#55) |
| `STRATIUM_MAX_DELEGATION_TTL` | `24h` | A delegation's lifetime (#17) |
| `STRATIUM_POLICY_EVAL_TIMEOUT` | `2s` | One evaluation of a tenant's policies (#17) |
| `STRATIUM_MAX_REQUEST_BYTES` | `4194304` | A whole request, and so `raw_input` (#59) |
| `STRATIUM_MAX_TOOL_BYTES` and eight more | see the guide | Each request field (#59) |
| `STRATIUM_PRINCIPAL_OIDC_KEY_REFRESH_INTERVAL` | `30s` | How often signing keys are fetched again (#62) |

### PAP

| Setting | Default | What it bounds |
|---|---|---|
| `STRATIUM_PAP_DB_MAX_OPEN_CONNS` | `10` | Database connections (#55) |
| `STRATIUM_PAP_OIDC_KEY_REFRESH_INTERVAL` | `30s` | How often signing keys are fetched again (#62) |

The PAP also refuses a request body over 1 MiB and closes a connection that
takes more than 30 seconds to send a request (#17). It has no connection limit
of its own: put that on the proxy that terminates TLS in front of it.

### PEP listeners (`proxy`, `extauthz`, `extmcp`)

| Setting | Default | What it bounds |
|---|---|---|
| **`STRATIUM_PEP_MAX_CONNECTIONS_PER_IP`** | `100` | Connections from one address (#69) |
| `STRATIUM_PEP_MAX_CONNECTIONS` | `10000` | Connections in all (#69) |
| `STRATIUM_PEP_MAX_CONCURRENT_STREAMS` | `256` | Calls in flight on one connection (#67) |
| `STRATIUM_PEP_MAX_CONNECTION_IDLE` | `5m` | How long an idle connection is kept (#67) |
| **`STRATIUM_PEP_PROXY_MAX_STREAM_DURATION`** | `1h` | How long one proxied call may stay open (#67) |

The [user guide](../user-guide.md) has the full description of each.

### What to check for your deployment

- **Behind a load balancer.** The per-address limit only tells clients apart
  when they connect directly. A load balancer or gateway that connects from
  its own addresses makes every client one address. Set
  `STRATIUM_MAX_CONNECTIONS_PER_IP` and `STRATIUM_PEP_MAX_CONNECTIONS_PER_IP`
  as high as the totals, and limit per client at the load balancer.
- **Many agents behind one NAT address** need the same two settings raised.
- **A gateway carrying heavy traffic under one delegation** can exceed 20
  calls a second. Raise the session call settings.
- **Several PDPs for one tenant** share the session call budget through the
  database (#72). The cap on audit entries for failed tokens is per PDP, so
  its tenant-wide ceiling is that rate times the number of PDPs.
- **Database connections.** Add up `STRATIUM_DB_MAX_OPEN_CONNS` for every PDP
  and `STRATIUM_PAP_DB_MAX_OPEN_CONNS` for every PAP that share a Postgres,
  and keep the total under its `max_connections`.
- **Long proxied streams** need `STRATIUM_PEP_PROXY_MAX_STREAM_DURATION`
  raised.
- **Identity tokens that list many groups** can exceed the 16 KiB credential
  limit. Raise `STRATIUM_MAX_CREDENTIAL_BYTES`.
- **Long URLs on the `extauthz` surface** count against
  `STRATIUM_MAX_TOOL_BYTES`, since the tool there is the request's path and
  query string.

A refused call says which limit it met. `Decide` answers `DENY` with the
reason; the other calls fail with `INVALID_ARGUMENT`, `RESOURCE_EXHAUSTED` or
`DEADLINE_EXCEEDED`.

## Retention

The PDP now deletes old sessions (#71). A session is a root delegation, the
delegations made under it and their approvals. Once every one of them expired
more than `STRATIUM_SESSION_RETENTION` ago (default `2160h`, 90 days), their
rows are deleted, and they no longer appear on the console's screens or in the
list routes.

**The audit log is not touched** and keeps the whole history. Each sweep that
deletes anything adds a `sessions_reaped` entry with the counts.

## New in this release

- **Human approval is configurable** (#1). An admin sets an agent's escalation
  threshold; a caller can only make it stricter. See
  [Require approval](../journeys/require-approval.md).
- **More harnesses.** `hook` supports Claude Code, Codex, OpenCode, Cursor,
  GitHub Copilot CLI, Antigravity CLI, Kiro CLI, Goose and Devin
  (#18 to #30), each with [a page of its own](../pep/README.md).
- **A system-level hook install** (#15) that puts the hook entry, the binary
  and its configuration where only an administrator can write.
- **Reports of completed tool calls** (#16). A tool call that ran in a
  governed session with no `ALLOW` on record is flagged on the Delegations
  screen and in the audit log.
- **LiteLLM guardrails** for MCP gateway calls and chat tool calls (#31), and
  **agentgateway** support through `stratium-pep extmcp` (#33). See
  [LiteLLM](../pep/litellm.md) and [agentgateway](../pep/agentgateway.md).
- **Protected policies** (#63). An admin can protect a policy so an editor can
  neither rewrite nor disable it.
- **The Approvals screen shows when an approval was used** (#51).
- **Limits in the example Envoy configuration** (#70):
  `deploy/docker/envoy.yaml` shows connection, timing and rate limits and
  circuit breakers for a listener in front of `stratium-pep`.

New audit event types: `unmatched_tool_use`, `call_budget_exceeded`,
`sessions_reaped`, `policy_protected` and `policy_unprotected`.
[Investigate what an agent did](../journeys/investigate.md) shows how to read
the audit log by event type.

## Verifying the upgrade

1. **The PDP starts.** A missing required setting, an unusable certificate, an
   unreachable identity provider or a superuser database role stops it with a
   message naming the cause.
2. **A session starts.** `stratium-pep session-start` succeeds with a
   principal token.
3. **A decision is made.** Run a tool call through your PEP and find it in
   `GET /v1/audit`.
4. **An approval round-trips,** if you use them: a call that escalates waits,
   an admin approves it, and the call runs once.
5. **The hook entries are current.** `deploy/stratium status` and `doctor`
   report a timeout that is too short or a missing reporting entry.
