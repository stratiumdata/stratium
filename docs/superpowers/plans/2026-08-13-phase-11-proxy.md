# Phase 11 — The gRPC proxy enforcement surface

Implements spec §3.2 **A2**/**A6** for the `proxy` mode — the fourth and last
enforcement surface. Four tasks.

**This completes A2.** `hook`, `mcp`, and `extauthz` ship; `proxy` is the
remainder. It is the second network intermediary, so it inherits Phase 9's
tokens (**A10**) and Phase 8's per-tenant catalog, and it is a **blocking**
surface (§4.6): unlike `extauthz` it can hold a call while a human approves.

## The shape, and what it can and cannot enforce

**Transparent forwarding.** The agent points its existing gRPC client at the
proxy and speaks the target's own protocol unchanged. No agent modification —
which is the thing that makes a proxy worth deploying at all, and the reason
this was chosen over the predecessor's `ExecuteActionRequest` envelope (§4.2),
which required every agent to be rewritten against a Stratium-specific API.

**P1 — the tool identity is the full method**, `/package.Service/Method`.
Catalogable per-tenant exactly as `write_file` and extauthz's path are; Phase
8's catalog is what makes this surface workable.

**P2 — the token arrives in gRPC metadata, `authorization: Bearer`.** No token
denies; there is no alternative credential (**K4**).

**P3 — `raw_input` is the method and metadata, credential headers stripped, and
deliberately NOT the message body.** The body is arbitrary protobuf for which
the proxy has no schema. Two consequences, both to be documented rather than
worked around:

- **Resource constraints and classification caps still bind — on the method and
  metadata, not on message contents.** A tenant can catalog `resource_field:
  "method"` and constrain a delegation to `{method: "/inv.Inventory/GetItem"}`.
  Coarse but real. What cannot be expressed is "may read item 7 but not item 9".
- **The evidence rule (§4.4.1) has nothing to scan on this surface.** Raw input
  carries no command text, so a tier comes from the catalog or the built-in
  classifier and never from a destructive-pattern match. **Do not feed opaque
  protobuf bytes into `raw_input` to give it something to scan** — binary data
  matching a shell pattern by coincidence is a false denial with an
  inexplicable reason, and it would make the audit digest meaningless.

**P4 — a stream is authorized once, at open.** The method is known then; the
messages are not parseable. Client-streaming, server-streaming, and
bidirectional streams each get exactly one decision, at open. Per-message
authorization is not possible without target schemas and is out of scope —
document it plainly, because an operator will assume otherwise.

## Global constraints

- Go 1.25, module path `stratium`, module root `services/`.
- **The PEP classifies nothing, decides nothing, and extracts nothing** beyond
  the structural. No method allowlist, no "reflection is harmless" exemption, no
  health-check shortcut. Those are spec defect **D1**, and on a proxy D1 is an
  open relay.
- **Fail closed, always.** No token, an invalid token, an unreachable PDP, an
  unreachable target, a malformed frame — every one denies and **nothing is
  forwarded**. A proxy that forwards on error is not a proxy with a bug, it is
  an unauthenticated tunnel.
- **`ESCALATE` blocks** — `proxy` is a blocking surface (§4.6). Reuse
  `awaitApproval`; do not write a second poll loop. This is its third caller,
  so if it needs reshaping again, that is a finding about the seam.
- **Never log tokens, metadata, message bodies, or approval ids.** This surface
  carries entire request payloads.
- `internal/authz` stays pure and is not touched.
- Strict root `.golangci.yml`. Clean before each commit, from `services/`:
  `go build ./...`, `go vet ./...`, `go vet -tags integration ./...`,
  `go test -race ./...`, `golangci-lint run ./...`. Plus `make conformance` and
  `make integration` from the repo root.
- Conventional commits, no attribution trailers — check each message.
- Scratch work goes in the session scratchpad, never the repository.

## Task 1 — Transparent forwarding, denying by default

**Files:** `services/cmd/stratium-pep/proxy.go`, config, tests.

Add `proxy` as a mode. It listens, accepts any method via an unknown-service
handler with a passthrough codec, and forwards to a configured target — **but
authorizes nothing yet and therefore denies everything.**

**Deny-by-default is not a placeholder here, it is a safety property.** A
forwarding skeleton that allows is an open relay the moment it is deployed, and
Task 1 of Phase 10 established the precedent: its `Check` denied until Task 2
gave it something to decide with. Test it explicitly.

**Handle unary and streaming from the start.** Retrofitting streams onto a
unary-only proxy means reworking the codec and the handler, and a proxy that
silently breaks streaming is worse than one that never claimed to support it.

**Configuration:** a listen address, the target address, and the PDP address,
agent id, subject, and connect timeout the other modes require, plus the
escalation poll interval and timeout `hook` and `mcp` already need. Required
values have no defaults, and a missing one fails at startup naming **all** of
them — a recent task found that loading two config groups in sequence hides the
second group's gaps.

**There is no session file** — the token arrives per request, as with
`extauthz`. Say so in the config's doc comment; a reader who knows `hook` will
look for one.

**Tests:** the proxy starts; a unary call is denied and **not forwarded** —
assert the target was not contacted, not merely that the caller got an error; a
streaming call likewise; a missing config value fails startup naming all;
the mode is reachable from dispatch.

**Mutation-test and report survivors:** make the skeleton forward instead of
deny; make streaming fall through unauthorized; report only the first missing
config key.

## Task 2 — Authorize, and block on escalation

**Files:** `services/cmd/stratium-pep/proxy.go`, tests.

Build a `DecideRequest` per **P1**–**P3**: tool from the full method, token from
metadata, `raw_input` from method and metadata with credential headers stripped.

**Strip credentials by omission and case-insensitively.** Never add
`authorization`, `cookie`, or `proxy-authorization` to the map that becomes
`raw_input`. That map is hashed into the **append-only** audit chain: a token
leaking there is live authority written permanently into a record designed to be
retained, and the chain cannot be edited to remove it. Phase 10 Task 2 settled
the header list and the reasoning — follow it, and **assert the absence
structurally across several casings**.

**Do not send `declared_tier`.** Assert its absence, as all three other modes do.

**ESCALATE blocks.** Reuse `awaitApproval` from `escalation.go`. A timeout
denies and does not forward. **This is `awaitApproval`'s third caller** — Phase
6 found it had baked the hook's stdout-and-exit-code contract into its logic and
split out a transport-free `resolveApproval`. If it needs reshaping again, say
what and why; that is a finding about the seam, not a failure of this task.

**On ALLOW, forward and stream the response back faithfully** — including
trailers and status. A proxy that drops a trailer breaks any client relying on
gRPC status details, and the failure will look like the target misbehaving.

**Tests:** an allowed unary call reaches the target and its response returns; a
denied one never reaches it; an allowed stream forwards in both directions; an
escalating call blocks then forwards on approval; an escalation timeout denies
without forwarding; the request carries no `declared_tier`; `raw_input` never
carries a credential header in any casing.

**Mutation-test and report survivors:** forward on DENY; leave `authorization`
in `raw_input`; treat an escalation timeout as allow; drop trailers.

## Task 3 — The limits, written down

**Files:** `docs/pep.md`, package docs, and tests that pin the documented
behaviour.

Three limits an operator must know, each of which will otherwise be discovered
as a surprise in production:

1. **A stream is authorized once, at open** (**P4**). Every message on an
   established stream rides that one decision. A revocation mid-stream does not
   terminate it.
2. **Authorization cannot see message contents** (**P3**). Resource constraints
   and caps bind on method and metadata only. State what *can* be expressed —
   `{method: "/inv.Inventory/GetItem"}` — and what cannot: "item 7 but not item
   9".
3. **The evidence rule has nothing to scan here.** On `hook` and `mcp` a
   destructive command in `raw_input` raises the tier regardless of the catalog.
   On this surface the tier comes from the catalog or the built-in classifier
   alone, so **an uncatalogued method takes the classifier's default** — and a
   tenant deploying this surface should catalog its methods deliberately.

**Write a test for each documented limit**, so the documentation and the
behaviour cannot drift apart. A limit that is documented but untested is a limit
that quietly stops being true.

## Task 4 — Against a real gRPC service, and the conformance sweep

**Files:** `deploy/docker/`, the integration suite, a scratch run.

**Put a real gRPC service behind it.** Every surface in this project was proven
against the real thing it was built for, and each such run found something no
constructed test had — Phase 10's found that real Envoy passes `:method` and
`:path` as literal header entries and injects `x-forwarded-proto`, neither
visible to a hand-built request.

**Prove, against a live stack:**

1. A valid token for a permitted method **reaches the target** and the response
   returns intact, trailers included.
2. A valid token for a denied method **does not reach the target**.
3. No token denies — no fallback (**K4**).
4. A token naming a **revoked** delegation denies at the **delegation leg**
   (**K3**).
5. An escalating call **blocks**, then forwards after an out-of-band approval —
   the blocking counterpart to Phase 10's non-blocking degrade, and the
   distinction §4.6 draws between the two surface classes.
6. A **stream** is authorized once at open and forwards in both directions.

**Then the conformance sweep — all four surfaces now exist.**

`TestC19_UnreachablePDPDenies` says every surface denies when the PDP is
unreachable and there is no valid cache entry. Its skip reason has cited missing
surfaces since Phase 4. **Read what it actually asserts.** All four now exist;
whether the "no valid cache entry" clause is satisfied by there being *no cache
at all* is a judgement call — **make it explicitly and justify it either way.**
If it converts, unskip it and report the tally. If it does not, correct the
reason. **Do not force a pass**; C19, C21, C22, C24, and C25 were each left
skipped honestly, and C23 converted only when a real Envoy proved it.

Re-check C20, C24, and C25 while there — all three still want the decision cache
or DPoP, neither of which this phase builds.

Tear everything down; verify no stray containers.
